# Работа над Notea

## Подготовка

Используй Go из `go.mod`, Node.js из `.nvmrc` и Docker Compose v2.
Выполни `make install`. Запуск приложения и переменные окружения описаны в
[README](README.md).

## Перед pull request

1. Создай ветку от актуальной `main`.
2. Внеси связанный набор изменений и обнови документацию, если меняется запуск или API.
3. Выполни `make check`.
4. Для изменений интерфейса и пользовательских сценариев запусти backend и
   `make test-e2e`; приложи скриншоты к PR.
5. Опиши, какую проблему решает PR и как проверен результат.

`make fmt` форматирует Go-код. ESLint проверяет handwritten-файлы frontend;
`vue-tsc` проверяет типы в TypeScript и Vue. Генерируемые клиенты не редактируются
вручную: меняй protobuf-контракт и обновляй результаты генерации одновременно.

При изменении зависимостей коммить соответствующие `package.json` и
`package-lock.json` вместе. Инструменты качества находятся в `tools`, зависимости
приложения — в `web`. Не добавляй в Git `.env`, токены, содержимое базы, сборки
и отчёты тестов.

## Проверки GitHub

PR запускает Go checks, Web checks, Browser tests и Docker builds. Если браузерный
тест упал, скачай артефакт `browser-test-results`: там HTML-отчёт, trace и логи
сервисов. Coverage находится в `go-coverage`.

Для сообщения о проблеме используй шаблон issue: шаги воспроизведения,
ожидаемый и фактический результат, ОС и браузер.
