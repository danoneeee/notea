# Note Flow

Этот файл описывает текущий рабочий flow заметок в веб-приложении.

## Текущие маршруты

- Основная авторизованная зона живет под `/app`.
- Список заметок: `/app/notes`
- Создание заметки: `/app/notes/new`
- Просмотр заметки: `/app/notes/:noteId`
- Редактирование заметки: `/app/notes/:noteId/edit`
- Старый путь `/notes/new` оставлен как redirect на `/app/notes/new`, чтобы не ломать старые ссылки.

## Пользовательский сценарий

1. Пользователь попадает в `Заметки` внутри `AppShell`.
2. Нажимает `Новая заметка` и открывает мастер создания.
3. Заполняет 4 шага формы.
4. Может сохранить промежуточный черновик локально.
5. После публикации заметка появляется в ленте `/app/notes`.
6. Из списка можно открыть detail-страницу, затем перейти в редактирование или удалить заметку.
7. Для авторизованного пользователя заметки синхронизируются с backend, но локальная копия остается источником быстрого доступа и оффлайн-резерва.

## Мастер заметки

`src/pages/NewNotePage.vue` остается одной формой для двух режимов:

- создание новой заметки;
- редактирование существующей заметки.

Шаги мастера:

1. Базовая информация о чае
2. Параметры заваривания и выбор сохраненного сетапа
3. Дескрипторы через `DescriptorWheel`
4. Оценки, свободный текст, ощущения чашки и цвет заметки

Особенности:

- у заметки есть стабильный `id`, который используется и локально, и на backend;
- при `fresh=1` создается новый draft id;
- при редактировании форма заполняется из существующей `NoteRecord`;
- можно выбрать `noteColor`, который затем подсвечивает заметку в списке и в detail view;
- шаги валидируются до перехода вперед и перед публикацией.

## Локальное хранение

Сервис `src/services/notes.ts` хранит данные в `localStorage`:

- `notea_note_draft` - последний черновик;
- `notea_notes` - локальный список заметок;
- `notea_note_sync_meta` - локальные метаданные синхронизации;
- `notea_pending_note_deletes` - очередь удалений для отправки на сервер.

Локальное хранение нужно для:

- оффлайн-работы;
- быстрого открытия списка и detail view;
- безопасного восстановления состояния, если сервер временно недоступен.

## Синхронизация

Для авторизованного пользователя включается sync с backend API.

- публикация или редактирование сначала обновляет локальную копию;
- затем заметка ставится в очередь на отправку;
- статусы заметки: `local`, `syncing`, `synced`, `error`;
- удаления тоже ставятся в отдельную очередь;
- при гидрации с сервера локальные и удаленные заметки мержатся по `id` и `updatedAt`.

UI сейчас показывает индикатор только для заметок, которые еще не находятся в состоянии `synced`.

## Где смотреть код

- shell и вкладки: `src/pages/AppShellPage.vue`
- список заметок: `src/pages/NotesPage.vue`
- просмотр заметки: `src/pages/NoteDetailPage.vue`
- создание и редактирование: `src/pages/NewNotePage.vue`
- клиентская модель и sync: `src/services/notes.ts`
- transport и auth refresh: `src/services/apiTransport.ts`
- backend API-обертка: `src/services/noteApi.ts`
- роуты: `src/router/index.ts`

## Что важно помнить при следующих изменениях

- `NewNotePage` используется и для create, и для edit, поэтому изменения формы нужно проверять в обоих сценариях.
- `notes.ts` отвечает не только за CRUD в UI, но и за merge/sync semantics.
- Любое новое поле заметки нужно синхронно добавлять:
  - в `NoteRecord`;
  - в форму;
  - в protobuf / backend;
  - в маппинг API и merge logic.
